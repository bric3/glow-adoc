= Performance

== Runtime behaviour

The pager paints source text before syntax highlighting and diagram rendering complete.
Highlighted spans are cached per source, language and appearance. Resize reuses them. Literal code
splits at line endings without segmenting every grapheme. Prose retains grapheme-aware wrapping.
Direct output waits for complete highlighting.

Only visible diagrams are requested, after the first text frame. One background worker renders them;
completion replaces the source without losing the viewport's block and relative row. Theme changes
retain the previous image while rendering its replacement. Closing cancels queued work and processes.

Images upload on first display. Scrolling updates placement/crop commands and retains the pixels in
the terminal. PNG files stream without decoding or re-encoding; other formats convert once.
Unchanged frames emit no graphics commands. Missing terminal images are uploaded again on ENOENT.
The off-screen residency target is 128 MiB of decoded pixels; visible images remain resident even
when their working set exceeds that target. All owned image IDs are released on exit.
This is terminal image residency, not a JVM heap limit.

== Document caches

Packaged applications cache AsciidoctorJ's normalised XML for regular file inputs. A hit reconstructs
the document model without starting JRuby. Layout, terminal detection, image access and highlighting
still run for the current invocation. No background service is required.

Entries live under `$XDG_CACHE_HOME/glow-adoc/conversions`, falling back to
`~/.cache/glow-adoc/conversions`. Windows uses LOCALAPPDATA or `~/AppData/Local`.
Each input path retains one variant, replaced after source or settings change.
The key covers source bytes, base directory, attributes, shortcode policy, application bytes,
JDK version, user home, locale and time-zone environment. Restoring a file timestamp does not hide edits.

A normal warmup primes the selected file's converted output. A new file, source edit or changed
attributes miss that entry and start AsciidoctorJ/JRuby again. Repeat-open measurements describe
documents with valid entries, rather than the first open of an arbitrary document.

Stdin, non-regular inputs, documents that process includes and sources referencing date/time attributes
are not cached. Exploded development classpaths are also excluded. Entries are limited to 8 MiB;
invalid, inaccessible and corrupt entries fall back to conversion. Cached XML uses the same secure parser.

Cache files contain converted document text. New directories are private and files are owner-only
on POSIX systems. Writes replace entries atomically where supported. `--no-cache` bypasses reads and writes.
Delete the conversions directory to remove retained converted text.

Completed syntax highlighting lives in the sibling `highlights` directory. Entries contain source text
and terminal styles. Source, language, appearance and application bytes validate each entry;
the decoder checks colours, links and exact source preservation. A hit skips Lumis/Wasm initialisation.
Stdin and exploded classpaths are excluded. `--no-cache` bypasses both document caches.

Each directory has a 128 MiB soft target. The first write in an invocation removes the oldest entries
when existing content exceeds that target; new entries can exceed it until the next invocation.
This is a disk cache policy, separate from terminal image residency and JVM heap usage.

The CLI disables JRuby native extensions by default because Java handles document files.
`-Djruby.native.enabled=true` restores JRuby's native support. JVM compiler and GC defaults are retained.

== Local AOT cache

Pre-train locally before installation:

[source,sh]
----
./gradlew :cli-jvm:install
----

The task trains a staged executable named `glow-adoc`, then installs it with its original timestamp.
The JVM permits relocation when the filename and timestamp match. The launcher validates the full
executable bytes, filename and runtime before selecting that cache; its directory is not part of the key.
`:cli-jvm:installWithoutAot` copies the executable without training. An existing compatible cache
can still be selected at runtime.

To train an existing installation:

[source,sh]
----
glow-adoc --train-aot
glow-adoc --timings document.adoc
----

The default workload is the project-owned link:../fixtures/aot/README.adoc[training corpus], bundled
in the jar. Original examples exercise includes, conversion, HTML, tables, lists, nested quotations,
five admonitions, disclosures, callouts, eight code languages and local image references. The CLI
extracts the listed files into a private temporary directory and removes them afterwards.
Training does not read an external document or user/project configuration. It bypasses both document caches
and does not open a pager or execute diagram programs. `--train-aot FILE` selects a custom workload.

`./gradlew :cli-jvm:aotTrain` prepares the staged executable and local cache without installing.
A later `:cli-jvm:installWithoutAot` can reuse them with the same runtime and JVM options.

A trained AOT cache can serve other documents: the document argument is not part of its identity.
It does not preconvert other files or retain an AsciidoctorJ engine between CLI processes.
Each document still needs its own valid conversion entry to bypass JRuby startup.
Additional document features can load classes absent from training; they run normally.

Caches live under `$XDG_CACHE_HOME/glow-adoc/aot`, falling back to `~/.cache/glow-adoc/aot`.
Identity includes executable bytes and filename, selected Java path and complete JDK release metadata,
OS/architecture and JVM option environment. `JAVA_OPTS`, `JAVA_TOOL_OPTIONS`, `JDK_JAVA_OPTIONS`
and `_JAVA_OPTIONS` participate in identity. Train again after any of these change.
New cache filenames start with a build-generation hash covering the launcher template and Shadow jar.
This hint only skips impossible lookups: training and possible hits still hash the entire executable
and validate the complete runtime identity. Manually editing a jar while retaining its generation hint
therefore invalidates existing caches. Caches from earlier launcher formats require retraining;
an executable update already invalidates their identity.
Pre-training uses the locally selected JDK. These caches are not universal release artifacts:
application, JDK build, platform and JVM option changes require compatible training.
No cache means normal startup; incompatible/corrupt cache loading
uses the JVM's auto fallback and may report diagnostics on stderr.

The launcher supplies the same compressed-reference compatibility flags during training and loading.
Explicit AOT flags, Java agents and flight-recording options in these variables bypass automatic selection.
Help and version skip cache hashing. Direct `java -jar` invocation does not select these caches automatically.
Training and possible matches enter the manager's environment before resolving the runtime and JVM
option variables. This adds a shell invocation only on these AOT paths. Ordinary launches delegate
directly to the manager. AOT requires JDK `release` metadata and `sha256sum` or `shasum`; without
them, ordinary startup still works and explicit training reports an error.
Remove obsolete cache files from the cache directory when they are no longer needed.

For direct Java invocation, train and load an explicitly named cache with the same JDK and jar:

[source,sh]
----
java --sun-misc-unsafe-memory-access=allow -XX:+UnlockDiagnosticVMOptions -XX:+AOTCompatibleOopCompression -XX:AOTCacheOutput=glow-adoc.aot -jar cli-jvm/build/libs/glow-adoc-0.1.0-SNAPSHOT.jar --no-cache --no-pager --color=always fixtures/showcase.adoc
java --sun-misc-unsafe-memory-access=allow -XX:+UnlockDiagnosticVMOptions -XX:+AOTCompatibleOopCompression -XX:AOTMode=auto -XX:AOTCache=glow-adoc.aot -jar cli-jvm/build/libs/glow-adoc-0.1.0-SNAPSHOT.jar document.adoc
----

== Reproduce measurements

Use an installed Java 27 and JBang. Run benchmarks without concurrent builds or other benchmarks:

[source,sh]
----
glow-adoc --no-pager --color=never document.adoc
jbang --java 27 tools/Benchmark.java --runs 20 --pty -- glow-adoc document.adoc
jbang --java 27 tools/Benchmark.java --runs 20 --stages -- glow-adoc --timings document.adoc
jbang --java 27 tools/Benchmark.java --runs 20 --pty --empty-cache -- glow-adoc document.adoc
jbang --java 27 tools/Benchmark.java --runs 20 --scroll -- glow-adoc -a image-assets="$PWD/static/assets" content/posts/post.adoc
jbang --java 27 tools/StartupMatrix.java /path/to/java cli-jvm/build/libs/glow-adoc-0.1.0-SNAPSHOT.jar document.adoc
----

`--pty` measures process start to the first status line in an 80 x 24 pseudo-terminal.
`--scroll` additionally simulates a Kitty reply and measures 20 single-line scrolls, output bytes
and image uploads. It requires an image in the initial viewport. Frame latency ends at the next
synchronised text-frame completion; it does not measure physical display latency.
CSV output reports each fresh JVM launch, median and nearest-rank p95. Polling adds measurement overhead.
The first launch is retained. Later launches normally have warm filesystem caches.
`--empty-cache` assigns a new temporary XDG_CACHE_HOME to each launch and removes it afterwards.
It measures an empty application cache; it does not clear the OS filesystem cache. Seed the default
cache before measuring repeated opens. `--no-cache` excludes cache lookup and writing altogether.

The matrix compares defaults, JRuby compilation disabled, tier-one compilation, their combination,
invokedynamic settings, and Serial GC with a bounded heap. Inputs are small, supplied and larger synthetic documents.
These are experiments, not recommended JAVA_OPTS defaults.

`--timings` reports cumulative milliseconds from command execution: configuration/input, JRuby ready,
conversion, first pager frame/image, highlighting completion or direct output completion. JVM launch and manager discovery
precede that timer and are included in the external benchmark.
A conversion hit reports `conversion-cache-hit` and omits `jruby-ready`.

The launcher also emits phase markers on stderr with `--timings`: entry, manager selection, AOT runtime
identity, artifact hashing, cache-key construction and JVM execution. `Benchmark.java --stages`
timestamps these markers and application milestones from the parent process. It implies `--pty`
and requires `--timings` in the application command. Marker observations include the benchmark's
5 ms polling interval; the launcher does not start clock processes. `command-*` rows start at a
marker immediately before command execution, excluding PTY, shell and `stty` setup. The ordinary
run rows retain the complete process-start timer.

Normal startup uses `mise exec -- java`, SDKMAN!'s current candidate, `asdf exec java`,
`jenv exec java`, or jabba's configured JDK, in that order. The first available manager owns runtime
selection and errors. With no manager, the launcher runs `java` on PATH; `JAVA_HOME` alone does not
select a runtime. No version probe, JDK search or installation runs. The Java bootstrap checks the
actual running JVM's minimum version. Manager execution can still take time.

Only AOT training and possible hits read the installed JDK's `release` file, containing version,
vendor and build metadata. Checksum parsing uses shell builtins. When AOT lookup has already hashed the artifact,
the launcher passes its canonical path and SHA-256 through the internal JVM properties
`glowadoc.launcher.artifact` and `glowadoc.launcher.sha256`. The cache accepts the digest only when
the path identifies its own runtime jar and the value contains 64 hex digits. Missing or
invalid launcher hash metadata falls back to hashing the jar. Full-content hashing and cache identity remain in use;
this avoids reading the same jar twice during one launch.

For a startup recording, pass `-XX:StartFlightRecording=filename=startup.jfr,settings=profile` to Java
and inspect it with `jfr summary` or a JFR viewer. Keep profiling separate from timed comparisons.

For complete direct output, Hyperfine measures fresh processes and peak RSS. Seed the document caches
with one warmup before measuring repeated opens:

[source,sh]
----
hyperfine --runs 3 --warmup 1 --output pipe --export-json output.json \
  'glow-adoc --no-pager --color=always -a image-assets=/path/to/static/assets /path/to/post.adoc'
----

Start async-profiler with the JVM to include startup work. Select the library for the current OS
(`libasyncProfiler.dylib` on macOS, `libasyncProfiler.so` on Linux):

[source,sh]
----
java --sun-misc-unsafe-memory-access=allow \
  -agentpath:/path/to/libasyncProfiler.dylib=start,event=cpu,interval=1ms,collapsed,file=cpu.collapsed \
  -jar cli-jvm/build/libs/glow-adoc-0.1.0-SNAPSHOT.jar \
  --no-pager --color=always document.adoc
----

temporary home. Required-mode loading succeeded after relocation, and conversion caching remained

== Investigation decisions

[cols="2,4",options="header"]
|===
|Candidate |Decision
|Image decode/encode per frame |Removed; reuse uploaded data and crop in the terminal.
|Full image retransmission |Removed from scrolling; only placement commands change.
|Eager syntax highlighting |Deferred until the first readable pager frame.
|Highlighting during reflow |Cached by source/language/appearance.
|Launcher subprocesses and repeated probes |Retain manager priority and runtime validation; version-only launch was approximately 0.2 seconds.
|Java executable discovery cache |Deferred: invalidation adds complexity to a small measured contribution.
|JRuby compilation and JVM compiler limits |Benchmark separately; flags that help parsing can slow highlighting.
|Invokedynamic, heap and GC settings |Included in the experiment matrix; no unmeasured default changes.
|AOT training coverage |Default installation trains the bundled corpus, including highlighted output; `installWithoutAot` skips training.
|Persistent JVM |Deferred by design; it adds process lifetime, isolation and memory costs.
|Converted-document disk cache |Implemented for self-contained files; source/settings/application hashes validate entries. Includes and temporal substitutions bypass it.
|Off-screen diagrams |Wait until visible; serial background rendering starts after the first text frame.
